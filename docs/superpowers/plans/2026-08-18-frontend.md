# Plan 2：前端实现计划（管理端 + 问答端）

> 目标：双端 Web 前端（管理端 /admin + 问答端 /），对接已完成的 collector(8002) 与 qa_api(8003) 后端。
> 依据：spec `docs/superpowers/specs/2026-08-18-school-knowledge-hub-design.md` 第 7 节 + ADR-009（Vue3 + Element Plus）。
> 派活：kimi-k3 批量（ADR-011）；本计划每个 Task 为自包含简报。

## 0. 技术决策（已定，勿改）

| 项 | 决策 |
|----|------|
| 框架 | Vue 3（Composition API）+ Vite + Element Plus |
| 流式渲染 | markstream-vue（markdown 增量渲染） |
| 图表 | echarts（统计页） |
| 路由 | vue-router：`/` 问答端、`/admin/*` 管理端 |
| 状态 | 不引入 Pinia（YAGNI），用组合式函数 composables |
| API 访问 | **Vite dev proxy 同源转发**：`/admin-api/*` → `http://localhost:8002`，`/qa-api/*` → `http://localhost:8003`（避免 CORS 与端口硬编码） |
| SSE | **fetch + ReadableStream 手动解析**（/api/chat 是 POST，EventSource 不支持 POST） |
| 测试策略 | 仅对纯逻辑（sseFetch 解析器、时间格式化）写 vitest 单测；组件不写单测（YAGNI），验收靠 `npm run build` + 联调冒烟 |

## 1. 后端接口契约（前端唯一对接依据）

### 管理端（同源 `/admin-api`，实为 collector:8002）

| 方法+路径 | 请求 | 响应 |
|---|---|---|
| GET `/admin-api/api/admin/sources` | - | `{"items":[{id,name,list_url,adapter,enabled,interval_minutes}]}` |
| POST `/admin-api/api/admin/sources` | `{"name","list_url","adapter","enabled","interval_minutes"}` | `{"id"}` |
| DELETE `/admin-api/api/admin/sources/{id}` | - | `{"deleted":bool}` |
| POST `/admin-api/api/admin/tasks/{source_id}/run` | - | `{"started":true,"source_id"}` |
| GET `/admin-api/api/admin/tasks?source_id=&limit=` | - | `{"items":[{task_id,source_id,status,succeeded,failed,started_at,finished_at,failures}]}` |
| GET `/admin-api/api/admin/knowledge?status=&category=&topic=&page=&page_size=` | - | `{"items":[{doc_id,title,url,publish_date,category,topics,status,expire_at,department,source_site,chunk_count,ingested_at}],"total"}` |
| POST `/admin-api/api/admin/knowledge/{doc_id}/status` | `{"status":"active\|archived"}` | `{"updated":bool}` |
| GET `/admin-api/api/admin/stats` | - | `{"total_docs","by_category","by_status","by_topic","recent_tasks","qa_total","hot_queries"}` |
| POST `/admin-api/api/admin/expiry-check` | - | `{"expired_count":int}` |

### 问答端（同源 `/qa-api`，实为 qa_api:8003）

POST `/qa-api/api/chat` body `{"query":str,"topic":str|null,"history":[{role,content}]}` → SSE 事件流：

| event | data | 前端动作 |
|---|---|---|
| `chunk` | `{"delta":"文本"}` | 追加到当前回答（markstream 增量渲染） |
| `sources` | `{"sources":[{doc_id,title,url,publish_date,category,expired}]}` | 渲染来源卡片（expired=true 显示"可能已过期"标签） |
| `done` | `{"query_id","elapsed_ms","answer_len"}` | 结束转圈 |
| `empty` | `{"message":"..."}` | 渲染"未找到"提示气泡（助手侧） |
| `error` | `{"message":"..."}` | 渲染错误气泡 |

## 3. 任务分解

### Task F1: 前端骨架 + API 层 + 路由

**Files:** package.json、vite.config.js、index.html、src/main.js、src/App.vue、src/router/index.js、src/api/request.js、src/api/sseFetch.js、src/api/admin.js、src/api/chat.js、src/utils/format.js、tests/sseFetch.test.js

**Interfaces:**
- `request(path, {method, body})` → Promise<json>：baseURL 用相对路径（`/admin-api` 或 `/qa-api` 前缀由调用方拼好）；非 2xx 抛 `Error(中文消息)`
- `sseFetch(url, body, callbacks)`：callbacks = `{onChunk(delta), onSources(sources), onDone(info), onEmpty(msg), onError(msg)}`；实现：fetch POST → `resp.body.getReader()` → TextDecoder 按行切 `event:`/`data:` 块 → 分发回调；**先写失败测试再实现**（tests/sseFetch.test.js 用 mock Response 流）
- vite.config.js proxy：
  ```js
  proxy: {
    '/admin-api': { target: 'http://localhost:8002', changeOrigin: true },
    '/qa-api': { target: 'http://localhost:8003', changeOrigin: true },
  }
  ```
- router：`/` → ChatView；`/admin` → AdminLayout（子路由 sources/tasks/knowledge/stats，默认重定向 sources）
- `format.js`：`formatDate(iso)`、`STATUS_TEXT = {pending:"待执行",running:"执行中",success:"成功",partial:"部分失败",failed:"失败",active:"在用",archived:"已下架",expired:"已过期"}`、`STATUS_TYPE = {running:"primary",success:"success",partial:"warning",failed:"danger",...}`（供 el-tag）

**Step 1:** 初始化：`pnpm create vite frontend --template vue` → 装依赖 `pnpm add element-plus vue-router markstream-vue echarts` + dev 依赖 `vitest`
**Step 2:** 写 tests/sseFetch.test.js（mock ReadableStream，覆盖 chunk/sources/done 分发与空流 empty 兜底）→ `pnpm vitest run` 确认失败
**Step 3:** 实现 sseFetch.js 与其余文件 → 测试通过
**Step 4:** `pnpm build` 成功；`pnpm dev` 起服务，浏览器访问 `/` 与 `/admin` 不报错
**Step 5:** commit `feat: 前端骨架+API层+sseFetch解析器`

### Task F6: 问答端聊天界面（SSE 流式 + 来源引用）

**Files:** src/views/chat/ChatView.vue、components/MessageList.vue、SourceCard.vue、TopicSelect.vue

**Interfaces:**
- 布局：顶部标题栏"校务智能问答"+专题域选择（TopicSelect：全部/六大专题 el-select）；中部消息流；底部输入区（el-input textarea，Enter 发送 Shift+Enter 换行，发送按钮）
- 消息流 MessageList：用户消息右侧气泡；助手消息左侧：Markdown 流式渲染（`<MarkStream :markdown="assistantMsg.content" />` 来自 markstream-vue）+ 回答结束后来源卡片列表（SourceCard）
- SourceCard：标题（link 新窗口打开 url）+ 元信息（分类·发布日期）+ expired 时橙色"可能已过期"标签
- 交互契约：发送 → 立即 push 用户消息与"生成中"助手占位（loading 转圈）→ sseFetch 回调 onChunk 追加 delta → onSources 后把 sources 挂到该助手消息、停止 loading → onDone 结束 → onEmpty 用返回 message 替换占位 → onError 显示错误气泡；发送中禁用输入
- 会话历史：内存数组（不落库，YAGNI）；每条提问带 topic 参数；自动滚动到底部
- 空态：首次进入显示欢迎语 + 3 个示例问题按钮（"2026年新生报到需要带什么材料？"等）

**Step 1:** 实现 → `pnpm build` 成功
**Step 2:** 联调冒烟：dev 起前端 + qa_api:8003 在跑（无数据时验证 empty 提示与示例问题交互；若后端有数据则验证流式渲染与来源卡片）
**Step 3:** commit `feat: 问答端聊天界面(SSE流式+来源引用+专题筛选)`
