# ADR-001: 三服务分层架构 + 双端界面

- 日期：2026-08-18
- 状态：已接受

## 背景
项目同时包含两类负载：采集/解析/向量化（重任务、可等待）与在线问答（低延迟、需即时响应）。且主题要求"中台"形态（管理端+问答端）。单人 + AI 协作，约 1 个月开发期。

## 决策
采用三服务分层：`collector`（采集服务，知识的生产与治理）、`qa_api`（问答服务，知识的消费）、`model_server`（本地模型服务，BGE-M3 + reranker）。前端为 Vue 3 单应用双布局（问答端 `/` + 管理端 `/admin`）。服务间不互相调用业务逻辑，只通过 HTTP API 与共享存储通信。

## 备选
- 单服务一体化：开发快但负载耦合、架构叙事弱，撑不起"中台"——否决。
- 极简 MVP（脚本+关键词检索）：技术深度不足——否决。

## 后果
- 正面：重/轻负载分离，独立部署扩容；架构与主题"中台"契合；复用 DocMind 拆服务经验。
- 硬约束关联：单机 Docker Compose 可复现（全服务一个编排文件）。
- 重新评估触发：若部署复杂度成为瓶颈（如连续多次环境问题），可考虑先合并为单进程部署再逐步拆分。
