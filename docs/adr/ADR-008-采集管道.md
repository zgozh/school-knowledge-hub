# ADR-008: 采集管道选型（httpx+selectolax+trafilatura+APScheduler）

- 日期：2026-08-18
- 状态：已接受

## 背景
采集对象是广州大学官网/新闻网等静态大学 CMS（无 JS 渲染），规模几百~几千页。需增量去重、中文正文提取、定时调度、失败重试。

## 决策
- 爬虫：httpx（AsyncClient）+ selectolax（解析），站点适配器模式（主站/新闻网各一个适配器，新增站点只写适配器）。
- 正文提取：trafilatura 为主（中文 F1 最高）；失败时 DeepSeek 兜底结构化提取；仍失败标记"待人工处理"。
- 增量去重：URL 哈希 + 内容哈希（md5），入库前查重。
- 调度：APScheduler（AsyncIOScheduler），采集源周期可配。
- 近重复合并：simhash（知识治理简化版）。

## 备选
- Scrapy：大规模中间件管线，本规模属过度设计——否决。
- Playwright：JS 渲染不需要——否决。
- Celery/arq：需 Redis broker，单机单服务属过度设计——否决。
- readability-lxml/goose3：中文 F1 低于 trafilatura——备选但不用。

## 后果
- 正面：最轻量链路满足需求；重试/幂等/任务状态机保证可观测可恢复。
- 硬约束关联：零内网依赖（公开网页即可跑）。
- 重新评估触发：若目标站点改版为 JS 渲染，再引入 Playwright 适配器（适配器模式已预留）。

## 人工资源依赖
无（公开网页）。
