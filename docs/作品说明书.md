# 作品说明书：面向校务管理的 AI 自动数据采集与知识管理中台

## 一、作品简介

**一句话定位**：自动采集广州大学多源校务信息形成知识库，师生自然语言提问即获「100% 附来源引用」可信答案的校务知识管理中台。

**立项三问结论**：

- **给谁用**：广州大学师生与校务行政人员——解决「校务信息散落在官网、新闻网等多处，办事流程与制度规定不知去哪查」的痛点。
- **什么不能妥协**：①答案可信（每条答案附可点击来源，无来源不编造）；②空环境一条命令可复现（docker compose）；③演示可离线（模拟数据脚本内置、确定性）。
- **第一版砍掉什么**：不做对话记忆窗口、用户权限体系、RAGAS 评测等（spec §11 范围外清单）。

## 二、创新点

1. **多源异构自动采集管道**（主创新）：站点适配器模式（主站/新闻网各一，新增站点只写适配器）→ httpx+selectolax 爬取 → trafilature+LLM 兜底解析 → URL/内容哈希+simhash 增量去重 → 任务状态机（待运行/运行中/成功/部分/失败）+ 单页失败隔离。
2. **可信问答**（主创新）：每条答案 100% 附来源引用卡片（标题可点击、栏目/日期、过期预警）；时间衰减 + 过期降权 + 断崖截断；知识库无相关内容时诚实回答「未找到」并给建议方向，**绝不编造**。
3. **湾区特色专题知识域**（辅助）：六大专题域（新生入学/港澳生服务/教务学籍/后勤生活/就业创业/科研学术），规则+LLM 双级打标，LLM 失败规则兜底（专题不落空）。
4. **知识全生命周期管理**（辅助）：采集→自动分类打标→时效标注→幂等三写入库→到期检测/上下架→资产全景（指标卡+图表+近期任务+热门问题）。

## 三、系统架构

```
┌─────────────────────────────────────────────────────┐
│                  前端（Vue 3 SPA）                    │
│     管理端：采集源配置·任务监控·知识库管理·资产全景     │
│     问答端：聊天界面（SSE 流式 + 来源引用卡片）         │
└──────────────┬───────────────────────┬──────────────┘
               │ HTTP/SSE               │ HTTP
┌──────────────▼────────────┐ ┌─────────▼───────────────┐
│    问答服务 (qa-api)       │ │   采集服务 (collector)    │
│  检索→重排→LLM流式生成      │ │ 调度→爬取→解析→向量化→入库  │
│  来源引用·问答日志          │ │ 任务状态·增量去重·重试      │
└──────────┬────────────────┘ └──────────┬───────────────┘
           │                             │
      ┌────▼─────────────────────────────▼────┐
      │    本地模型服务（FlagEmbedding FastAPI）   │
      │  BGE-M3 双向量(dense+sparse) + reranker  │
      └─────────────────────────────────────────┘
           │
┌──────────▼─────────────────────────────────────────────┐
│              共享存储（Docker Compose 统一编排）           │
│  Milvus    → 向量检索（dense+sparse 混合）                 │
│  MongoDB   → 元数据/任务状态/问答日志/统计                 │
│  MinIO     → 原始HTML快照·附件                            │
└─────────────────────────────────────────────────────────┘
           ▲
   DeepSeek（主 LLM）/ DashScope（降级兜底）
```

**职责边界**：采集服务=知识的生产与治理；问答服务=知识的消费；本地模型服务=向量化与精排推理。服务间不互相调用业务逻辑，只通过 HTTP API 与共享存储通信。

**数据流四条主线**：①采集流（定时触发→列表页→增量去重→详情页→正文提取→元数据→时效→切分→向量化→三写→任务日志）；②问答流（提问→混合检索→重排→上下文组装→流式生成→来源引用→问答日志）；③管理流（采集源配置→任务监控→资产全景→到期归档→人工上下架）；④知识管理流（入库→双级打标→时效→统计→到期降权→审核→全景）。

## 四、关键技术

- **检索链路**：BGE-M3 dense+sparse 双路召回 → min-max 归一化融合（0.8/0.2）→ 时间衰减（半衰期 30 天）→ 过期降权（×0.25）→ bge-reranker-large 交叉编码精排 → 断崖截断（0.3）。（ADR-006 参数）
- **采集管道**：httpx（异步）+ selectolax → trafilatura + LLM 兜底解析 → 规则（一级分类）+ LLM（专题域，失败规则兜底）双级打标 → 幂等三写入库（先删后插）。
- **降级链**（spec §8）：LLM 主 DeepSeek 挂 → DashScope 备援；reranker 挂 → 保留原序；sparse 索引挂 → 仅 dense；MinIO 挂 → 快照缺失标记（主链路不断）。

## 五、运行与部署

```powershell
# 1. 复制 .env.example 为 .env，填入 BGE_M3_PATH / RERANKER_PATH / DEEPSEEK_API_KEY
# 2. 一条命令起全栈（存储 + 三后端 + 前端）
docker compose up -d --build
# 3. 播种演示数据（可选；幂等可重跑）
uv run python -m scripts.seed_demo
# 4. 打开 http://localhost:5173（问答端）；管理端 http://localhost:5173/admin
```

- 前端构建产物由 nginx 托管，API 反代与开发态同构（`/admin-api/`→collector 去前缀、`/qa-api/`→qa-api 去前缀、SSE 关闭缓冲）；SPA 路由回退支持 `/admin` 直接刷新。
- 模型权重本地挂载（BGE-M3 与 bge-reranker-large 各一个目录），无需云端模型服务。
- 本机开发态仍支持三终端 uvicorn + `pnpm dev`。

## 六、演示数据与验收

- **真实采集**：广州大学官网通知公告 8 篇 + 新闻网头条关注 11 篇（真实管道运行，含 4 篇失败隔离记录——证明「单页失败不拖垮整体」）。
- **模拟数据**：六大专题域 18 篇内置模板，`scripts/seed_demo.py` 确定性生成、幂等可重跑（跑两遍仍 18 篇）。
- **验收实测**：
  - 后端 pytest：**53 passed**（单测+全链路集成测试真跑存储，含真实 LLM 生成段）；
  - 前端：vite build 退出码 0 + vitest **9 passed**；
  - 20 题演示问题清单逐题实测：**20/20 = 100% 附来源引用**；
  - 空环境复现：一条 `docker compose up -d --build` 起全栈（本机实测，含 nginx 双端代理验证）。

## 七、技术选型决策（ADR 摘要）

| 编号 | 决策 | 一句话理由 |
|------|------|-----------|
| ADR-001 | 三服务分层 + 双端单 SPA | 生产/消费负载差异拆服务；双端共享知识底座 |
| ADR-002 | 向量库 Milvus | 混合检索（dense+sparse）原生支持 |
| ADR-003 | 元数据库 MongoDB | 文档型天然贴合异构文章元数据 |
| ADR-004 | 对象存储 MinIO | S3 兼容、单机可复现 |
| ADR-005 | 本地模型服务（FlagEmbedding FastAPI） | BGE-M3 双向量 + 重排本地推理，不依赖云模型 |
| ADR-006 | 检索链路参数与时效感知 | 时间衰减/过期降权保障答案时效可信 |
| ADR-007 | LLM：DeepSeek 主 + DashScope 降级 | 主链路失败备援兜底 |
| ADR-008 | 采集管道 httpx+selectolax+trafilatura+APScheduler | 静态 CMS 站点够用且轻量 |
| ADR-009 | 前端 Vue 3 + Element Plus | 双端单应用、管理表格开箱即用 |
| ADR-010 | 数据策略：真实采集 + AI 生成模拟脚本 | 真实证明能力、模拟覆盖演示场景 |
| ADR-011 | 开发模型分工与批量派活 | 规划/评审/集成与前后端开发路由到不同模型 |
